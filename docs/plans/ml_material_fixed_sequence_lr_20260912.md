## 新模型与路线规划是否需要重新适配

当前调用链：ActiveRgbdRuntime → EquipmentDetector → 检测框/类别/置信度 → RGB-D与时间过滤 → ActiveInspectionPlanner。如果保持四类设备及输出契约，通常无需改写规划算法，但训练完成不等于可直接替换上线。

代码核对事实：

- src/flight/active_rgbd_runtime.py读取模型包manifest.json，检查权重相对路径与SHA256，使用冻结检测阈值；缺少manifest时回退到规划stable_confidence。
- config/perception/active_inspection_policy.json的稳定登记阈值为0.60，巡检置信度目标0.85。开发推理阈值0.37与这两个值不是同一层次；不应把它们一并改成0.37。
- src/vision/evaluation/detector.py输出EquipmentDetection并按已知四类名称过滤；新模型必须检查名称/编号、输入颜色、框坐标和640输入契约。运行时predict目前未显式传入NMS IoU与max_det，因此接入验收还需核对与冻结评估协议的有效参数是否一致，不能仅凭框接口相同认定行为等价。
- 模型身份通过权重哈希写入规划policy。不能只以best.pt/last.pt文件名作为新模型身份。

合格新模型后续需要独立打包与接入验收：冻结权重/阈值/类别映射；同帧比较离线与运行时预测；核对深度定位、连续登记与重访决策；测推理延迟和过期帧处理；再进行隔离的规划闭环回归。规划参数仅在证据表明必要时另立对照调整。当前实验模型均未晋升，不能直接用于飞行。

本次代码检查和已有规划单元测试并不等于新模型已经完成飞行适配；没有在实飞或封存场景运行新模型。
