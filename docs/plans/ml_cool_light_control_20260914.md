# 冷色光照条件覆盖对照

## 判断依据与边界

上一轮 IL1000 的中性低光训练成员拟合诊断为三个 seed 各 52/52 实例命中，但开发光照条件表现未稳定改善。这支持检查条件覆盖，不足以确定唯一根因。世界参数核对发现：训练采用中性低光，已查看开发条件采用偏冷光照。IC1000 固定对照这两个物理光照配方。

本轮新增数据仅是已有八个训练位姿的 32 张光照派生图，覆盖原始／暖／冷／中性四种设备材质；不新增独立位姿或资产。配方取自已查看开发条件，明确属于已知开发条件适配，不是盲测或独立场景泛化证明。开发图像和标签不转入训练，保护参考只读取排除索引，不解封新场景。

## 数据和审核门禁

独立目录为 `cool-light-coverage-v1`。新世界仅改变环境光为 `0.38 0.42 0.48 1`、太阳 diffuse 为 `0.58 0.66 0.78 1`。几何、设备材质、相机和实例映射保持各自来源配置。

四张试点通过后展开其余 28 张。每帧检查 canonical 采集门禁、完整标签与来源一致、框差不超过一像素；每帧用独立重放的连续三帧验证 RGB 完全一致及映射实例覆盖。每个目标都有自己的裁剪和 AI 辅助观察，汇总器只导入显式记录。

中性材质顶面可能与地面近色，部分后柜下缘局部遮挡；审核记录保留限制。背景非目标柜体、建筑与设备实例分开记录，不能只凭外形改身份。文件与原尺寸 RGB 去重，并核验开发位姿不重合；共享布局和资产仍如实披露。

## 唯一训练策略差异

直接参考为 LR=0.0005 的 IL1000 三 seed，不是最新 LR=0.00025 家族。原采集模板中六单元、顺序尾部实验字段已由 `condition-audit.json` 勘误；本训练协议为三个新增单元 IC1000-7/17/27。

沿用 IL1000 的实际交错曝光顺序，将 300 次中性低光成员曝光按唯一来源替换为冷光对应成员，保持原来的 50 个完整批次位置。不改变其他 5700 个位置、负例位置、完整类别实例与谱系曝光、亮度系数或总预算。每 50 步账本在实际序列生成后冻结。

三 seed 均从 v2.11 独立初始化：CPU、640、batch/nbs=6、AdamW、恒定学习率 0.0005、无预热，1000 优化步，仅冻结亮度增强，使用终点 last.pt。沿用两个独立训练进程、每进程四 Torch CPU 线程的加速选择；第三 seed 在前两个完成后运行。

## 执行入口

1. `python -m scripts.vision.cool_light_capture --capture`：采集，非试点需要试点审核回执。
2. `python -m scripts.vision.verify_cool_light --replay`：逐帧精确重放。
3. `python -m scripts.vision.record_cool_light_review`：导入逐图逐实例显式审核。
4. `python -m scripts.vision.prepare_cool_light_training`：导出、冻结与真实加载预检，绝不训练。
5. `python -m scripts.vision.train_cool_light --train`：需有效就绪回执，显式启动。
6. `python -m scripts.vision.evaluate_cool_light --after-training`：训练全体完成后一次性正式／低阈值评估，不自动生成审核意见。

预检三个配置实际遍历 18000 次加载：完整标签张量与同 seed 历史 IL1000 相同，未替换批次图像张量和逐图增强记录必须完全相同。禁止创建优化器、反向传播或训练验证。启动再次核对输入、回执和 v2.11 固定 40 文件。

## 评估和结论

评估继续使用已查看的 48 张配对开发图和 48 张无目标开发图，CPU、640、confidence 0.37/0.001、类别相关 NMS IoU 0.7、max_det 300、同类一对一匹配 IoU ≥0.5。不改门槛；能力保留仍按 retained_reference-450 和历史 A 的原始／光照全图及逐类召回 5 个百分点容差。IL1000 只作为直接策略比较，不冒称正式能力保留基准。

训练成功不是模型通过；数值完成也不自动代表审核通过。新权重全部保持 `training_admitted=false`、`promotable=false`。结果仅用于判断同预算冷色条件覆盖是否改善已知开发条件，以及是否伴随其他能力代价，不追加临时配比或挑选 seed。
