## 处理边界

不得重签或覆盖旧文件使历史证据看似有效；不得重新创建临时路径冒充当时环境。相关旧数值和审核需要明确标注可复核范围。

下一步区分两类依赖：

1. 新训练集必须依赖的原始图像、完整标签、来源映射、逐图审核和角色隔离：重新独立核验，并在新版本中绑定实际证据；不能仅复制旧通过状态。
2. 历史优化求解环境及旧实验结论：保留缺口。若作为新训练对照或曝光约束来源，则必须有独立可复核证据，否则阻断对应比较。

N05 原有暂缓不因其旧审核身份失效而恢复；U29 具名覆盖风险仍隔离。全部新产物 training_admitted=false、promotable=false。当前尚无可用训练集完成回执，未启动训练。

## 后续定位：两份身份失败的可复现解释

进一步检查创建代码和签名函数后，发现签名前的 Python 字典具有整数键，而 JSON 读取后这些键变成字符串；排序序列化的顺序因此变化。

在内存副本中（不修改历史文件），仅将以下已知字段的数字字符串键恢复为整数，保留其余所有内容，即可逐字节哈希复现两份记录保存的原始 identity：

- reviewed-hold 的每个 frame.instance_mapping。
- N05 审核的每个 record.visible_pixels_by_label。

因此，两项失败已有“整数键 JSON 往返导致签名不稳定”的可复现解释，不再将其表述为尚无解释的内容变化；这不证明其他依赖全部有效，也不撤销 N05 的风险结论。原生 verifier 仍拒绝旧文件，必须通过独立、字段限定的兼容核验及全部直接输入检查建立新回执，不能全局忽略 identity 或任意转换所有数字键。
