## 评估与验收规则

1. 主任务是四类检测，报告 mAP50-95、macro-F1、每类 precision/recall、小目标召回和无目标帧误检率。基线保留 0.37；候选只用验证集按既有 macro-F1 规则选阈值，进入保留测试前冻结。
2. proposal 仅作辅助定位诊断：640 输入、class-agnostic NMS IoU=0.7、最多 16 框、匹配 IoU≥0.5；现有通过条件为总召回≥98%、有样本类别召回各≥95%、截断后框数 P95≤16。背景误检率目前没有进入此函数的 passed 条件。
3. 后续增加截断前候选数、饱和率、截断召回损失和重复框率的诊断报告，不改变原有 16 框门槛。此步骤只是登记指标，尚未实现新统计。
4. 保持既有 v2.11 Complex qualification 条件：配对率≥95%、skew P95≤33.334 ms、各类召回≥95%、类别准确率≥90%、定位误差中位数≤1 m/P95≤2 m、探索覆盖≥90%。这份配置不能代表三地图都已通过，其他场景仍执行各自适用的既有验收流程。
5. 保持既有 PT/ONNX 等价与身份验证。当前没有统一的新四类 mAP/FPR 晋升阈值，不凭空制定数值或凭一项成绩自动替换官方模型。

训练只可使用 development 数据；blind/qualification 不用于训练或调参。允许使用其图像哈希进行排除检查，但保护清单完整性仍需确认。新视角按场景、录制/种子与视角谱系分组；最终准入前统一精确/近重复排查。

原始 v2 验证标签与部分后续同名 6,941 帧版本不一致，已固定本次采用原始 v2 版本。若复核发现标签问题，应新建修订版本并让所有候选和基线在同一修订版本重新评估，不覆盖本清单。v2.11 训练时的 40 帧 switchgear 快速验证成绩、run18 的单类 equipment mAP 均不能直接充当本基准的四类成绩。

## 使用与验证

在项目根目录运行：

```sh
.venv/bin/python scripts/vision/verify_experiment_baseline.py
```

校验器只读，检查清单自身身份、40 个引用文件哈希、完整模型包和数据成员关系。文件缺失或变化时返回非零退出码。首次核验记录保存在本地 `outputs/research/ml_training_recovery_v1/baseline_verification.json`。

这是需要显式运行的实验前检查，尚未自动接入训练 CLI。清单使用哈希检测变化，不会给文件设置只读权限，也不会替代训练入口原有 clean-worktree 检查。后续修改评估实现或被固定的证据时，新建清单版本并保留旧版；不要为了得到绿色结果改写旧版哈希。
