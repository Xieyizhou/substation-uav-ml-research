# 尺度端点拆分开发对照

用户授权执行拆分对照并判断结果。独立目录`scale-endpoint-control-v1`，不修改历史实验，不收新图、不改标签、不解封新场景；不创建定时或跨轮跟踪任务。

## 冻结设计

复用已核验固定640三个seed作共同参考，上一轮混合尺度只作背景比较。新增small、large两组，每组seed7/17/27，从v2.11独立初始化。small每单元300批320＋150批640；large为300批960＋150批640。两组恰好使用原混合尺度的300个非640位置，其余位置保持640；不重新洗牌，不拆分批次或改变批内顺序。

全程保持同seed的2700次成员曝光、完整类别实例曝光、450批、亮度系数逐位置相同，暂缓成员仍为零。CPU、batch/nbs6、AdamW、恒定LR0.0005、无预热、450优化步，除冻结亮度外增强关闭；只使用last.pt。缩放从640张量双线性插值得到，960不增加原生细节。

比较回答：在同一非640曝光比例下，小端或大端策略如何影响开发表现。不是上一轮混合端点每个批次的纯因果分解。优化步和曝光预算一致，计算预算不一致：small平均像素预算为固定640的0.5倍，large约1.8333倍。

## 门禁和执行

三个seed各两组真实加载器逐一遍历2700张；检查完整标签、原640亮度张量及有效缩放张量哈希、批次顺序和尺寸。禁止优化器、反向传播和训练验证。训练实际入口再次逐批比对预检张量；完整有效单元可复用，失败独立保存且最多三次技术尝试，语义失败停止。父进程异常和取消后清理本次子进程。

预检及针对性回归成功后连续运行六个独立训练单元，再执行固定开发推理，无需用户逐阶段确认。默认主入口只冻结／核验；显式连续命令：`.venv/bin/python -u -m scripts.vision.scale_endpoint_control --run`。

## 评估和判断边界

沿用48张配对开发图、48张无目标图；CPU640、confidence0.37/0.001独立推理、类别相关NMS IoU0.7、max_det300，同类一对一IoU≥0.5。保存全部逐实例得失、预测及诊断；重复seed不增加独立样本数量。

门槛及原始／光照能力保留仍相对retained_reference-450和历史A；另完整报告相对同seed固定640。不得调整阈值、挑seed、按结果改变比例或追加训练。原有邻柜待定风险不删除，全量指标保留；匹配竞争不能被归因成没有候选。

数值完成不等于错误审核完成或模型通过。两组若都不满足门槛，如实报告；若某端显示条件取舍，区分事实、支持性证据和未验证机制。所有产物training_admitted=false、promotable=false，不晋升模型。
