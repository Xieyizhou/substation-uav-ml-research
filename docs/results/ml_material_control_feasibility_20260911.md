# 材质训练可行性：证据修正与质量门禁阻断

## 当前状态

本阶段停在 `blocked_at_material_candidate_quality_gate`，尚未完成整套材质敏感性复核。停止依据是用户计划明确的“身份、标签或全图覆盖风险未解决时先处理监督风险”出口。本轮没有训练、采集、修改历史标签、调整阈值或解封新场景。

新目录 `data/research/ml_training_recovery_v1/material-control-feasibility-v1` 保存 `initial-gate.json`、240 个独立目标裁剪及其来源身份。所有产物保持 `training_admitted=false`、`promotable=false`。

## 已完成的检查

- 对48张开发图的240个真值分别从对应世界计划与原采集实例映射解析设备身份，检查类别、实际世界哈希与 `full_2d` 模式。重新执行现有四条件世界差异检查。该差异检查沿用既有工具，本轮没有据此新增像素级可见性认证。
- 每个真值按自身原尺寸坐标生成裁剪，记录完整真值哈希、图像哈希、设备身份及裁剪哈希。全部新审核状态为待逐框审核，未自动继承旧批准。
- 六个训练单元的实际曝光顺序与冻结计划一致，逐成员次数及原回执曝光汇总保存在新账本。这是曝光身份核对，尚未完成材质/视角/谱系覆盖普查。
- 核验封闭主体 warm/cool 八张候选的审核、审核完成及掩码覆盖回执：其直接身份检查通过，其中四张为暂缓，另外四张仅为审核候选。

## 上一轮证据勘误

1. 旧120条原始/光照分层记录中，**96条非计划目标的 `object_id` 错用了计划设备ID，96条裁剪关联指向计划目标裁剪**。原始图、真值框与这96条账本关联错误是不同层次；本轮没有认定96条历史训练标签错误。新的240条证据已经按逐实例重新关联，但尚未完成新的可辨性决定。
2. `metrics-v2.json` 读取 `review-v2.json`，其输入列表却绑定旧 `review.json`。旧 `review.json` 又因脚本变化而不能通过直接依赖校验。因此旧指标回执不能只凭顶层校验就声称完整链条有效。
3. 递归检查六个评估单元的上游时，发现历史 `reviewed-hold-compensation-control-v1/protocol.json` 自身份不一致。检查原生成脚本后，将其中实例映射键恢复为整数，精确复现保存身份 `fec050c5027faedc44a0f10399c24d0a5b51fb17b03527dccd87d96b84e8ddbb`。这是JSON键转换影响排序的可解释格式问题，不作为篡改证据；新初检回执保存原值、加载后计算值及重建值，历史文件未改动。
4. 原始分层不能被当作材质/背景/光照条件自身的可辨识性认证。先前49–51个百分点的材质差值仍是旧分组下的观察，本阶段尚未完成独立四条件审核，暂不把它升级为“颜色依赖已确定”的结论。

旧报告及脚本全部保留，本文件是增补勘误。旧报告写37项测试而回执实际为32项的表述，以回执为准；本轮测试范围和结果另见 `gate-validation.json`，不声明全仓测试通过。

## 下一阶段唯一优先建议

先制定并核验**独立的候选监督风险处理方案**：

1. 将T027和T036及已唯一解析的同源变体列入统一影响清单，追踪后续诊断和已有排除决定；不能只凭旧回执认定历史后续处理从未发生。
2. 对T027确认后续上游框/深度裁剪诊断是否已有解决证据，以及是否适用于该warm/cool原帧。若需要新的诊断重放，应独立冻结原样对齐控制；不向旧标签追加可见框。
3. 对T036明确完整图的内容风险处理。默认暂缓；任何重新收录应有新的具名逐框依据，不能靠改变面积门槛。
4. 恢复本阶段时，补完240条四条件独立审核、六单元评估核验、材质/视角覆盖矩阵及其他候选普查，再决定补采或固定预算材质替换。只有该门禁通过后才冻结训练序列。

当前可以回答：已发现可信的证据关联缺陷及明确的候选监督风险。尚不能回答：全部材质失败结构是否已被训练覆盖，或现有候选是否足以实现安全的固定预算材质替换。这两个问题明确保留，不用猜测形成训练方案。
