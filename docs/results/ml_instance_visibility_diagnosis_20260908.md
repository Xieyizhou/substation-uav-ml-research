# 实例可见性检测与标签风险确认

## 结论

本轮完成带具名缺口的检测闭环，不等于全部重放成功或标签问题已解决。27 个待定框对应的 23 张图全部通过唯一来源、原始 RGB 像素、世界哈希及实例映射核验；世界中各目标视觉组件的标签也与计划一致。

## 运行发现及处理

1. 初始实现只采三帧，四个视角都出现首帧少量 RGB 差异、随后两帧精确一致。改为十二帧有界窗口，按 RGB 与掩码内部字节一致性选择最早连续三帧，选择不依赖原图匹配成绩。实际稳定窗口为第 2–4 帧，未修改相机或世界条件。
2. 采集辅助程序在退出时发生异常；T095 的日志明确包含 `mutex lock failed: Invalid argument`。代码中 transport node 早于互斥锁、队列和回调对象构造，逆序销毁时可能在仍有订阅回调的情况下先销毁共享状态，这是与错误相符的生命周期缺陷。
3. 已提供修复版：让 transport node 在回调状态之后构造，从而先销毁订阅。修复版编译通过，**尚未进行实机重放验证**。原失败记录、原始程序和二进制保留，不覆盖失败回执，不追加第四次尝试。
4. T077/T095 保存的十二帧原始数据可做离线辅助核对；离线检查没有恢复完整运行退出状态及移动时间栅栏，不能替代失败回执。
5. 首次协议准备曾因整数 JSON 键导致身份排序差异而失败，已改为字符串键；失败准备记录保留。有效协议和运行回执均重新校验身份。

## 产物与接口

独立目录为 `switchgear-condition-review-v1/instance-visibility-diagnosis-v1`。

- `protocol.json`：冻结的 23 张图来源、27 个实例框、四帧试验、门禁及开发成员谱系影响范围。
- `replay/`：有界尝试、世界副本、原始 RGB／深度／掩码、位姿／框元数据、稳定窗口与差异图。
- `postfailure-check/`：与原失败记录分离的辅助检查，不产生认证。
- `review.json`、`frame-dispositions.json`：逐框 AI 辅助审核及全部 23 张图的处理状态。
- `tests.json`、`baseline-check.json`、`completion.json`：回归、固定文件完整性及带缺口的完成回执。

## 下一重要判断

目前足以确认两项极端截断风险，但不足以冻结全批数据修订方案。下一步应先在独立且重新授权的尝试预算下验证原生订阅退出清理修复，再完成 T077/T095 和剩余帧。不得将修复的编译通过当作运行验证通过，也不得将后方窄条风险解释为全部模型退化的唯一病因。
