# full_2d 实例 128：隔离运行时核验

## 重要判断

**已确认 T027 中实例 128 的主体在真实 full_2d 运行中进入投影边界排除分支。** 这不再只是数学复算：同一保存位姿的两次独立诊断进程各观察到三次一致分支；实例标签来自实际可见性映射，位置和尺寸唯一对应 `west_switchgear_02/body`。

结论仅针对这次漏框。它不能解释历次模型能力退化的全部原因，不代表整个渲染器已修好，也不能使极窄边缘残片自动获得训练准入。

## 隔离方式与身份修正

新增极小 `gz::sim::Server` 启动器，在独立进程、通信分区和尝试目录中加载原场景诊断副本。副本仍只增加上一阶段已经核验的实例传感器与 visible_2d 传感器；未修改设备、相机参数或原 full_2d 传感器。

LLDB 软件断点只存在于本次诊断进程内，读取寄存器与内存；没有执行目标表达式、写寄存器、强制分支或修改磁盘库。沿用保存位姿及三帧稳定、位姿、同步、RGB 和框一致性门禁。

第一次执行发现实际动态加载路径是 Homebrew 的 `lib/gz-rendering-8/engine-plugins/` 副本，而不是顶层库。两文件整文件哈希不同，不能互相冒充；它们的 UUID 和完整 FullBoundingBoxes 反汇编指令序列相同。首次记录原样保留，并新增 `verified-binary-v1`，在第二次执行前后绑定两份实际文件：

- 顶层库 SHA-256：`336cda8e141c9f25848134d87988bfc019b86c0d0841efea06dd805fd0f88f9a`。
- 实际插件 SHA-256：`015b8894053d9b75c9c15d06595ae376ac2fd7534eaa5233ced1cdfeb3b31b62`。
- UUID：`8FBF722A-207A-3417-B576-D1D9F28C9BC3`，arm64。

运行前冻结的反汇编、运行时加载路径、运行后哈希和首次身份局限均纳入回执。第二次确认不覆盖第一次，也没有重新生成历史标签。总共启动两次诊断服务器，没有无限重试。

## 实际观测

实际可见性表给出 Ogre item 78 → 标签 128；运行时部件位置 `(-13,-3.5,0.8)`、尺寸 `(1.72,2.58,1.44)`、单位旋转与保存主体唯一匹配。观察点位于 MeshMinimalBox 返回后，说明该 item 已通过前置可见性和视锥检查。

| 观测 | 数值或结果 |
| --- | --- |
| 实际投影 x 范围 | −7.9703655～24.2960949 |
| 实际投影 y 范围 | −42.4038544～66.1518021 |
| 实际分支目的位置 | FullBoundingBoxes 起点 +632，排除路径 |
| 每次重放的重复观察 | 3 次，均为同一主体且数值一致 |
| 运行时光心 | 约 `(-11.13525505,-4.76584833,3.00000005)` |
| 保存几何经实际矩阵的透视分母范围 | 约 −0.3994715～2.6398719 |

实际 x 区间横跨视口，但两个端点绝对值均大于 1。反汇编显示该条件把执行流送至排除路径；断点实际观察到了该目的位置。使用保存角点与运行时矩阵可以复算返回的 x/y 极值，误差小于 0.002 NDC；正负透视分母同时存在，支持未经近裁剪的跨相机平面顶点导致异常范围这一解释。

没有直接导出原始 VAO 顶点。函数返回值、矩阵与分支是运行时直接证据；角点和分母计算是附加复算证据，不能混称直接读取了所有内部网格候选。

两次重放均通过原图逐像素 RGB 一致性与原有 full_2d 框一致性检查。各自选择第 2、3、4 个采集帧作为首个内部稳定窗口；full_2d 均没有 128，visible_2d 与实例掩码均有 128，半开包围框 `[59,1052,306,1080]`，3534 像素。同步差均不超过 33.334 毫秒。

运行分支事件没有仿真时间戳，因此不将某一次断点事件强行对应到某一条传感器消息；这里报告的是同保存位姿下重复的运行证据及独立稳定帧检查。

## 验证及保留风险

38 项相关测试覆盖事件缺失／重复、加载库身份、实例及组件冲突、相机变化、错误投影、错误分支、RGB 不一致、同步失败和清理失败，并包含已有投影、双模式、来源追溯和可见性回归。汇总器开发时曾误把返回 z 当透视除法后的值；已按该函数保留未除 w 的 z 语义修正，并分别核验 x/y 和 z，未改变渲染器。

v2.11 固定 40 文件完整性核验及测试明细以 `verified-binary-v1/completion.json` 为准。不声明全仓测试通过。两次执行的 LLDB、debugserver 和专用服务器均已清理；“lost connection”出现在主动结束子进程时，不用于冒充正常服务器退出。

所有新产物保持 `training_admitted=false`、`promotable=false`、`training_ready=false`。未训练、未修改标签或阈值、未写入生产库、未读取保护标签或解封新场景。T027 的全图标签完整性风险和 T036 的可辨识内容风险仍未关闭。

## 下一步建议

优先在**独立渲染器测试构建**中验证近裁剪与投影边界处理修复，保留当前实例为固定失败用例，同时覆盖完全在镜头前、跨近裁剪面、完全在镜头后、横跨视口和完全出界的对照。仅替换绝对值判断不足以建立正确框语义；需先处理透视除法前的裁剪。

修复对照通过后，再制定独立标注版本和边缘残片监督政策，并检查受影响来源范围。不得把 visible_2d 直接混入现有 full_2d 标签，也不得在这些风险未关闭前恢复材质对照训练。本阶段止于技术问题确认，没有实施该后续修复。
