**已完成原版和修复版独立构建，修复版在固定 T027 场景中恢复实例 128。** 原图 RGB 未改变，原有五个实例框基本不变。这支持当前裁剪修复方向，但不等于生产发布或训练准入通过。

修复后 128 的连续坐标框约为 `[54.75878,1051.84570,305.73866,1080]`。同帧 visible_2d／实例掩码半开框仍为 `[59,1052,306,1080]`，3534 个实例像素。

两种框左边界相差约 4.24 像素：full_2d 几何范围与 visible_2d 可见范围本来不要求完全相同，但本轮未进一步确认这段差异对应的具体像素内容。因此只确认“漏框恢复”，**不认证新框可直接用于训练**，也不改写旧标签。

## 构建与修复范围

独立目录：`data/research/ml_training_recovery_v1/renderer-near-clip-test-v1`。

源码固定于 gz-rendering 8.2.3 的 Git 提交 `f1249da6e07f0d6b7adaba28109fa7af727fd322`。发布归档下载超时，未完整归档保留为失败产物，未解压或用于构建。Git 稀疏下载排除了不必要的教程图片，源码身份绑定于控制构建回执。

两版使用本机 AppleClang 21、C++17、Release、相同依赖与 CMake 参数；分别置于 `build` 与 `build-clipped`。关闭上游 BUILD_TESTING、跳过 Ogre1／OptiX，只构建 Ogre2 目标；本报告中的测试来自独立裁剪测试及本项目相关回归，不冒称通过上游全套测试。安装前缀指向项目内路径，**没有运行 cmake install，也没有修改 Homebrew 库**。

相对原版源码，已有文件只修改 `Ogre2BoundingBoxCamera.cc`，新增两个诊断头文件：

1. 按真实三角形索引读取网格，支持 FLOAT3／HALF4 顶点、16／32 位索引及无索引三角形列表。
2. 在透视除法之前对三角形做齐次视锥六面裁剪，避免相机后方顶点产生异常投影。
3. 以裁剪后的顶点计算范围，排除空范围和同侧出界范围，不再按两个端点绝对值误排跨视口区间。

诊断适配器仅支持三角形列表；不支持的类型明确失败。旧函数体在诊断入口提前返回之后保留，便于审阅差异；不是准备直接提交生产的最终代码形态。性能和更广泛网格兼容性尚未验收。

## 加载隔离与失败记录

前两次原版重放被身份门禁拒绝，均未进入有效对照：

- 首次缺少加载器使用的无版本插件名称。
- 补齐名称后，独立解析探针确认默认安装目录仍排在环境路径之前。

最终为诊断子进程设置项目内 `GZ_RENDERING_INSTALL_PREFIX`，同时明确指定原资源目录和变体插件路径。启动前探针先确认解析结果；运行时再次记录实际加载的 dylib 路径及哈希。第三次原版重放通过，修复版首次在该配置下通过。失败尝试均保留，没有覆写或无限重试。

实际进程同时加载安装版和本地构建的 core dylib。两版控制相同，且 RGB、原有框对齐支持本次实验可比性；这不是部署打包安全认证。生产接入前仍需整理依赖加载方式。所有专用服务器均已清理，生产库哈希核验保持一致。

## 测试、身份与边界

- 9 项独立 C++ 裁剪检查通过：视锥内部、完全出界、相机后方、近裁剪面之前、横跨视口、跨近裁剪面、跨相机面、空输入和非有限输入。
- 45 项相关 Python 回归通过：包含已有运行时核验、投影、双模式及可见性检查，并新增实例恢复、原有框漂移、RGB、缺帧、重复框和清理门禁测试。
- v2.11 固定 40 文件完整性核验通过；不声明全仓测试或上游全套测试通过。
- 协议、源代码差异、构建日志、库身份、加载探针、原始传感器输出、失败尝试及最终比较绑定于 `completion.json`。

同位姿的稳定帧是重复技术观测，不是新增独立样本。本轮只有一个真实场景帧，不支持全场景安全结论。所有新产物保持 `training_admitted=false`、`promotable=false`、`training_ready=false`；未训练、未改标签、未调整阈值、未解封新场景。
