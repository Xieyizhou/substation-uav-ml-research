# Batch内重排敏感：病因与解决方法

## 结论与范围

这次“相同batch只改变图片排列，训练结果就漂移”的病因链已经定位，并通过干预验证：

**FP32损失及反向汇总受排列影响 → 近零梯度出现符号/数值差异 → AdamW在当前裁剪与eps设置下放大更新差异 → 后续预测与正样本分配分叉 → 训练轨迹和终点评估不同。**

它不是本次首个真实batch中的图片/标签错位，也不是该batch前向或BatchNorm运行统计先发生变化。此前终点BN缓冲区差异大，不能倒过来认定BN是首因。

已验证的解决办法是规定唯一的有效batch内顺序，并在取图/拼接标签之前执行，记录原请求及实际顺序。两份独立100步验证的损失、参数、逐图预测完全一致。

**这是排列不稳定的完整诊断，不是“所有检测错误的唯一病因”。材质/光照敏感和普通柜体、建筑误检仍未解决；没有产生候选或晋升模型。**

## 1. 逐层排查证据

使用F与W首个真实训练batch，同一v2.11初始权重、CPU、8线程、FP32、相同优化器配置。W逆重排回F后：

| 检查 | 结果 |
| --- | --- |
| 归一化图像张量，7,372,800个元素 | 逐位一致 |
| 每张图的类别与框坐标 | 逐位一致 |
| 已捕获Conv/BN层输出及模型输出 | 逐位一致 |
| 任务对齐分配器的类别、框、分数、前景掩码及目标索引 | 逐位一致 |
| 首次前向后的参数/缓冲区 | 逐位一致 |
| 损失分项 | 出现约1e-6差异 |
| 原始梯度 | 最大绝对差约0.003902 |

正常训练模式、eval模式、只冻结BN的训练模式均做了核对。后两者仍出现损失与梯度差异。因此简单冻结BN并未在该单batch试验中消除分歧；也不能据此宣称冻结BN能解决当前问题。

这些结论针对实测batch和当前实现，不是所有数据标签都正确或所有后端算子都置换等价的证明。

## 2. 最早可观察的数值分歧

当前安装的Ultralytics损失实现使用 `target_scores.sum()` 归一化，并在BCE、框/DFL损失中进行汇总。正样本分数的元素在对齐后完全相同，但首batch汇总结果为：

| 汇总精度 | F排列 | W排列 |
| --- | ---: | ---: |
| FP32 | 78.20467376708984 | 78.20466613769531 |
| FP64对照 | 78.20466968882829 | 78.20466968882829 |

这是排列相关浮点归约误差的直接证据。正常训练首步分类损失分量（乘batch size后）分别为15.248682975769043和15.24868392944336。

反向传播也需要归约，因而不能把所有梯度差异量化归属到唯一一处`sum`；本次证明的是这条数值链，而非某一个底层CPU内核的唯一责任。源文件身份随证据冻结，没有更新Ultralytics或修改其安装文件。

## 3. 为什么微小误差变成明显参数差异

首步未裁剪梯度范数约193.1249，裁剪阈值10，缩放系数约0.05178。最大的首步参数分歧出现在`model.10.m.0.attn.qkv.bn.bias`的第189个元素：

| 数量 | F | W |
| --- | ---: | ---: |
| 裁剪前梯度 | -1.85566023e-7 | +2.67755240e-7 |
| 初始参数值 | -2.923828125 | -2.923828125 |
| 一次AdamW后 | -2.9233381748 | -2.9244091511 |

参数差约0.00107098。此bias属于不施加权重衰减的参数组，AdamW的`eps=1e-8`，学习率0.001。首步经偏差校正后的更新可写作：

`Δ参数 = -0.001 × 裁剪后梯度 / (|裁剪后梯度| + 1e-8)`

两侧近零梯度经过裁剪后正好与eps同量级，符号翻转被转化成相反方向的更新。按这条公式计算与实际更新在5e-7内吻合，已纳入回归测试。这不意味着所有小梯度都错误，也不意味着仅提高eps就能改善完整模型。

## 4. 连续20步的分叉与干预

在相同初始模型和AdamW状态下，重放真实F/W序列、相同裁剪及学习率：

- 第1步：参数最大差约0.001071，前景分配仍相同。
- 第11步：首次发现前景掩码有2个位置不同，梯度最大差约0.1672。
- 第20步：参数最大差约0.005510，前景掩码4处不同，梯度最大差约0.4558。

正样本选择的离散变化进一步改变训练分支；BN运行统计也会随已分化的模型轨迹改变。这解释了为什么仅看终点BN差异会误判起因。

控制组在每次取图前，按稳定成员ID统一batch内顺序，保留batch成员及批次先后。连续20步的损失、梯度、参数/状态和分配均完全一致。

该重放不做候选选择，20步阶段也不采用验证成绩筛选任何状态；它是定位与干预证据。

## 5. 已实现的处理方式

### 已冻结的实验：恢复既有参考顺序

使用 `scripts/vision/reference_batch_order.py` 中的 `align_to_reference(requested, reference)`：

- 每个batch先核对成员多重集，不接受跨batch移动或成员变化。
- 验证通过后，恢复该batch原先冻结的有效顺序。
- 例如W可精确恢复F的600次序列，B/G不能冒充批内排列被自动恢复。
- 不对历史实验重新排序或覆盖旧权重；原请求与有效序列必须分别登记。

这是保留已有基线行为的优先方案。F有效序列在此前已完成三个独立100步训练，并证明损失、参数和预测一致；本次额外验证了W到F的逐batch序列恢复。没有宣称又运行了一组新的“参考顺序恢复”终点训练。

### 新实验：先冻结唯一有效batch内顺序

使用 `scripts/vision/canonical_batch_order.py` 中的 `canonicalize()`，按稳定成员ID在每个完整batch内排序。应在dataset取图与collate之前执行，不要在图片拼接后仅重排图像而漏改标签索引。

实际集成入口为 `scripts/vision/validate_canonical_batch_fix.py`，保留 `requested_schedules` 和有效 `schedules` 两份账本。历史训练脚本行为保持不变；该策略需在新协议中显式启用，不是对所有训练入口的隐式全局补丁。

这个方案规定唯一计算顺序，不是让浮点加法变成交换操作，也不会消除B/G这类真实改变训练时间顺序或分组的影响。

## 6. 完整100步验证及质量边界

CF/CW各从同一v2.11独立开始，seed7，分别接收F/W请求并执行预先固定的batch内成员排序。两次100步训练实际有效序列相同，共200优化步、1200次图像曝光；实际成员、每张图次数、batch成员和batch先后均核验。

| 核对项 | 结果 |
| --- | --- |
| 10轮box/cls/DFL损失 | 完全一致 |
| 终点state_dict参数及缓冲区 | 完全一致 |
| 正式48张配对图与48张无目标图预测/匹配 | 完全一致 |
| 配对图conf0.001诊断预测 | 完全一致 |

两次训练不是两个独立数据样本，也不是三seed候选家族。该验证只检验排列不变性。

质量结果仍不合格：无目标19/48帧误检，FPR39.58%，共21个预测框；原始计划命中100%、材质50%、背景83.33%、光照58.33%。这组排序改变了F原来的有效计算顺序，不保证复现F原始指标，更不能当作检测性能优化。

**不要用这组验证权重替换现有模型。对现有冻结基线优先恢复原参考顺序，而非临时改为字典序。** 选择字典序时未查看本轮成绩，也不会因为它成绩不好而继续搜索别的排序。

## 7. 未解决的问题与后续路线

已经解决的是同一batch的无意义排列差异导致的可复现性问题。当前证据不能说明普通柜体/建筑误检、材质和光照敏感全部来自这个数值问题。之前逐框审核确认的视觉混淆仍然存在，现有质量门禁仍不满足。

后续模型改进应在固定有效顺序和完整曝光账本后，分别测试成员组成、重复曝光、整批顺序/训练预算；不要继续把这些变量绑在一个seed上。针对柜体/建筑几何、暗面板及遮挡的监督覆盖，需要独立的数据或模型实验验证。

优化层面的候选方向包括提高累加精度、检查近零梯度更新、单独评估AdamW eps或学习率设置；本次没有验证这些改动的完整检测收益，不能直接推荐某个新数值或把它们与采样变化同时加入。也没有证据支持现在直接换网络结构或只冻结BN。
