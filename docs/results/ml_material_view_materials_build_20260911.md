# 训练材料建立：世界草案完成，实际采集阻断

本轮没有训练、修改历史标签、恢复暂缓成员或部署渲染器。新增产物均为开发候选准备，`training_admitted=false`、`promotable=false`。

## 已建立材料

为上一轮仅视觉内容审核完成的N04、N05建立原始／warm／cool共6份SDF草案，位于 `material-view-candidates-v1/world-drafts-v1/`。它们属于两个开关柜计划目标位姿，不代表四类覆盖齐备，更不是6张已经采集的训练图。

原始外观追溯到哈希有效的 `complex-occlusion-filtered-plan-v1/world.sdf`。该历史世界使用visible_2d；新草案明确保留当前full_2d，不恢复旧标注语义。将历史材质更改还原后，核对全部XML结构，除允许的材质颜色外与当前保存来源一致。暖／冷仅修改计划目标主体ambient/diffuse两项，保留面板、基座、其他设备、几何、光照、相机和传感器不变。具体实际载体位姿记录在manifest中；启动世界本身不会自动完成位姿设置或采集。

这一步解决了“已有mat_cool_gray来源不能冒充原始组”的配置来源问题，**没有解决原始图像存在性、实际渲染一致性、全图标签及像素可见性问题**。10张整图暂缓来源未生成变体草案，未按审核成绩更换位姿凑数。

## 本轮实际重放及失败

冻结了两帧小规模原生渲染器核验：先N04控制帧，再N02蓝块归属疑点帧。仅在N04认证通过后才允许继续N02。

N04三次技术尝试均被新入口的时间戳预检错误阻断：Gazebo JSON的秒数字段为字符串，而入口进行了字符串与整数比较，抛出TypeError。三次失败独立保留，均完成进程清理；N02未启动，未获得任何原帧像素认证。此次错误属于新工具缺陷，不是数据质量不合格的证据，也不能据此判断渲染器不支持实例掩码。

三次预算已经用完，不清空目录或换编号继续采集。原入口及其冻结身份保持不动。新增了独立的时间戳解析修复函数：接受整数及protobuf整数字符串，拒绝缺失、非有限、分数或越界时间，针对性测试通过。修复尚未用于新的实际重放，不能称运行问题已被现场解决。
