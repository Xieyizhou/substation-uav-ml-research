# 仅深度平面裁剪：四位姿独立对照

## 结论

**仅深度平面裁剪版通过本轮四个固定既有位姿的技术门禁。** T027 的实例 128 恢复；四帧原有的 23 个框均保留，坐标相对原版的最大变化为 **0 像素**。没有重训模型，也没有将此结果视为训练准入或生产发布通过。

各位姿原图与重放 RGB 逐像素一致；三版实例掩码哈希一致。四个新单元均选择第 2、3、4 帧作为首个内部稳定窗口，配对时间差最大 32 毫秒，并通过实际位姿及相机合法性检查。

这些是四个登记位姿，不是四个独立场景；23 个框是跨帧记录数量，不等于 23 个独立设备或新训练样本。

## 单变量收窄

新目录为 `data/research/ml_training_recovery_v1/renderer-depth-clip-test-v1`。以六面裁剪版源码为起点，唯一行为改动是把裁剪平面循环从 0～5 改为 4～5：仅裁剪近、远平面，不裁左右、上下侧面。

三角形索引读取、顶点格式支持、同侧排除判断、相机配置和采集内容保持不变。原有完整投影极值仍先参与求框，再沿用既有屏幕坐标限制。使用相同 Release 配置、编译器及依赖，在新构建目录生成测试库；没有执行安装或覆盖旧构建。

原版和六面裁剪版对照复用已经通过身份核验的回执和输出；新深度版使用同四个保存位姿重放。没有按结果换图、改变阈值或增加实验位姿。

## 128 恢复后的框含义

T027 的新 full_2d 框为 `[0,1051.84570,348.40805,1080]`。它与六面裁剪版的 `[54.75878,1051.84570,305.73866,1080]` 不同，也不是 visible_2d 掩码框 `[59,1052,306,1080]`。

这是保留既有 full_2d 完整投影范围口径的结果：视口之外的几何仍可能决定包围矩形极值，之后才限制矩形坐标。**技术上恢复了完整标注输出，不代表框中已有足够可辨识内容。** 不把它直接写入历史标签，不将 full_2d 与 visible_2d 混用。

先前 `(94,1075)` 的单像素边界归属待定仍保留；本次没有通过修改像素、标签或面积阈值来消除待定。

## 启动时间戳阻断与处理

T020 首次启动在图像采集前遇到“位姿消息缺少秒字段”，被现有门禁拒绝。原失败回执和原未完成运行回执均保留；没有修改 canonical 时间戳解析器或把缺失秒字段自动视为零。

新增独立诊断时钟预检：最多六次消息读取、15 秒期限，要求显式、有限且合法的 `sec>=1` 后才进入既有移动后时间栅栏。采集阶段仍执行原来的同步门禁。T020 在 attempt-02 核验，其余位姿在 attempt-01 核验；没有进一步自动重试。

四次成功运行的时钟预检均首次读取到显式秒字段，仿真秒为 3；没有接受缺字段消息。这验证了正常显式时钟路径，但不将原缺字段的具体生成原因冒称已完整查清。

## 下一步与尚未完成事项

现在有证据把“深度裁剪版”作为后续标注链路修复候选，六面裁剪版仍不用于保持历史框口径的任务。

下一优先步骤是制定**独立标注修订与极端截断审核方案**：明确 128 这类仅剩边缘片段的监督处理、全图实例完整性及旧数据影响范围；继续保留 T036 的内容不足风险。不能因框已输出，就自动批准训练样本。

生产接入前还需更广泛的边界／资产回归、性能验证，以及消除当前诊断进程同时加载安装版和本地 core 库的打包风险。仅支持三角形列表的诊断实现也尚非通用生产版本。本轮未实施这些后续变更，未补采训练数据、未训练或解封新场景。
