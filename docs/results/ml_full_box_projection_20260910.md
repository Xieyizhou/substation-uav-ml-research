# 实例 128：full_2d 投影／裁剪隔离复算

## 结论与边界

已在独立数学复算中复现一个与漏框吻合的路径：几何跨过相机平面，未经近裁剪直接透视除法形成异常投影区间，随后触发端点绝对值排除条件。结合上一阶段同帧 visible_2d 和实例掩码都有 128、full_2d 没有 128 的实测，优先调查对象已收窄到 full_2d 的投影／裁剪处理，而不是训练模型、颜色变化或标签转换器。

这不是已完成的渲染器运行时分支认证。本次使用 SDF 长方体角点与针孔模型，没有抓取 Ogre 实际 VAO 顶点、投影矩阵或逐部件可见性过滤日志。不能宣布唯一根因，也不能把复算范围直接写回标签。

## 证据

输入固定为 T027 的已保存实际载体位姿、相机 link 偏移、原世界和上一阶段对齐通过的三帧回执。没有改动世界、材质、位姿或生产软件。

本机 Homebrew 安装声明为 gz-rendering 8.2.3，公式和安装回执纳入哈希。对应版本的 [Ogre2BoundingBoxCamera.cc](https://raw.githubusercontent.com/gazebosim/gz-rendering/gz-rendering8_8.2.3/ogre2/src/Ogre2BoundingBoxCamera.cc) 中，FullBoundingBoxes 使用两个端点绝对值均大于 1 的排除条件；MeshMinimalBox 透视除法前没有在该函数内做近裁剪。这是版本源码审读，不等于已证明安装二进制的实际执行分支。

实例 128（west_switchgear_02）逐部件复算：

| 部件 | 相机前向深度范围（米） | 未裁剪投影触发排除 | 近裁剪后投影范围与视口相交 |
| --- | --- | --- | --- |
| base | −0.394757～2.816110 | 是 | 否 |
| body | −0.399472～2.639871 | 是 | 是 |
| front_panel | −0.344485～0.052156 | 是 | 否，全部在 0.1 米近裁剪面之前 |

主体经近裁剪的最高 NDC y 为 −0.9478619003，对应像素上边界 1051.845426。此前实测实例掩码半开包围框为 `[59,1052,306,1080]`，有 3534 个像素。上边界差约 0.155 像素，是局部几何一致性证据，不是全相机标定或组件像素归属认证。几何投影不处理遮挡；本报告不把主体投影推断升级成逐像素组件审核。

独立反例也表明：NDC 区间横跨 −2 到 +2 时，原排除条件判为外部，而该区间实际覆盖视口。仅改成同侧区间判断还不够：必须先正确处理近裁剪／透视除法，不能把相机后方顶点投出的范围当有效框。

## 执行与校验

新增 `scripts/vision/diagnose_full_box_projection.py`，只读输入、执行解析复算和相关测试，输出独立 `dual-mode-v1/projection-probe-v1/diagnosis.json`。它不启动 Gazebo、不创建模型、不训练、不生成替换标签。

测试包含横跨视口反例、同侧与内部对照、近裁剪、全后方几何、零分母、投影轴约定、不支持的坐标变换拒绝，以及冻结 T027 复算。连同相关双模式、来源追溯和可见性回归共 27 项；最终运行结果及 v2.11 固定 40 文件核验记录于诊断回执。不声明全仓测试通过。

所有新产物保持 `training_admitted=false`、`promotable=false`、`training_ready=false`。历史标签、权重和生产渲染器未改变。

## 下一判断点

优先做隔离的渲染器级最小复现：记录该实例各 Ogre item 的可见性、相机矩阵、透视分母及排除分支，比较正确近裁剪后的诊断输出与已保存 RGB／掩码。应在独立构建或测试夹具中完成，不替换生产库，不以切换 visible_2d 混用标注口径作为修复。

确认技术问题后，再独立制定边缘残片的完整标注与监督政策，并对受影响来源做范围检查。当前 T027 标签完整性和 T036 内容不足风险仍未关闭，因此不恢复材质对照训练。
