# 同位姿 full_2d / visible_2d 框诊断

## 核心结果

**同一画面中，full_2d 缺少实例 128，visible_2d 则连续三帧输出该实例，且其可见边界与 panoptic 实例掩码一致。**

因此，排查范围进一步缩小到 full_2d 特有的完整框生成处理，而不是当前训练导出删框、材质变换或设备标签根本不可解析。尚未对 Gazebo 内部运行分支插桩，不能宣布具体哪一条投影、视锥或裁剪条件已经被证实为根因。

本轮没有修复历史标签、切换生产标注模式、修改已安装渲染器或训练模型。

## 对照设计

使用此前固定的 T027 原始来源、保存世界及实际载体位姿。不移动相机或设备，不改几何、材质、背景、光照。

保留原有 `research_boxes` 的 full_2d 配置，仅额外添加：

- 与 RGB 同配置的 panoptic 实例传感器。
- 原框传感器的副本，只改变传感器名称、独立 topic 和 `box_type=visible_2d`，其光心、视场、分辨率及其余设置保持一致。

新增独立 C++ 采集程序，同时订阅 RGB、深度、实例掩码、位姿、full_2d 和 visible_2d。直接保存两种完整原始消息，不过滤框或自动转换为训练标签。历史采集程序未修改。

第一次技术尝试完成。按首次 RGB/掩码内部稳定窗口选择捕获帧 2、3、4；visible_2d 框也在这三帧保持一致，没有按是否出现实例 128 挑选窗口。

## 实例 128 的对应结果

设备：`west_switchgear_02`，类别：开关柜。

full_2d 的输出仍只有 149、139、64、113、208，没有 128。

visible_2d 输出六个实例，其中 128 的原始像素端点为 `[59,1052,305,1079]`。按可见像素端点的包含式语义转为半开区间后，为 `[59,1052,306,1080]`，与实例掩码的外接范围完全一致。三帧实例像素数均为 3,534。

这里的加 1 是诊断中的坐标语义统一，不是对历史 full_2d 框应用偏移，也不是生成一条新的训练标注。visible_2d 表示可见部分，full_2d 表示完整框模式，二者不能直接混为同一监督定义。

## 已排除与未排除

已确认：

- 该设备标签能被当前环境的另一种框模式输出，且与实例分割对应。
- 本帧的原始 RGB 和原 full_2d 输出未因增加传感器而改变。
- 只有更换诊断框模式，实例 128 才出现在额外输出中；不是移动相机追求通过。

仍未确认：

- full_2d 内部究竟在哪个投影、裁剪、可见性或分组步骤丢弃它。
- 该问题对其他帧及实例的影响范围。
- 底边这类片段最终应标注、显式忽略还是整图暂缓；像素存在不等于类别监督内容足够。
- T036 实例 118 的独立内容不足风险，未因本次对照解除。
