# CPU推理加速测试及来源保留对照评估

## 加速判断

采用双进程、每进程实际4线程。固定小批为E-7与M-7两份终点权重、四条件各一张开发图及四张无目标图，双阈值各重复3轮。各配置使用相同输入，不训练、不搜索阈值。

| 配置 | 两模型总墙钟秒数（含进程启动/加载） | 与串行4线程逐框输出完全一致 |
|---|---:|---|
| 单进程4线程 | 10.34 | 是 |
| 单进程6线程 | 9.18 | 否 |
| 单进程8线程 | 9.29 | 否 |
| 双进程各4线程 | 5.19 | 是 |

本次小批总耗时约提速1.99倍，不承诺其他数据或训练同样提速。双进程每个worker推理耗时约2.62秒，比串行worker约2.28–2.36秒略慢，但整体吞吐提高。单worker峰值驻留内存约520MB；未测量系统同时峰值，不能把两worker峰值相加称为实测总峰值。

6/8线程在小批中未改变预测数量或类别，但最大框差分别约0.00055/0.00046像素，置信度差约1.1e-6/3.1e-6，故按预定严格一致性规则排除，不称这些微差导致模型退化。

实测推理库初始化会将线程数设置成8；新入口在初始化后明确设置并逐帧核验4线程。以前只在初始化前写set_num_threads(4)，不足以证明实际推理使用4线程。此次发现不是对历史训练实际线程数的追溯认证。

## 全量数值评估完成

六份权重分别完成48张配对开发图和48张无目标图的0.37/0.001两套推理，合计1152次正式协议预测调用，不包括小批复核。双进程执行、验证与汇总约81.46秒；这不是与串行全量对照测得的加速倍数。E-7和M-7在全量入口中的固定小批复核与串行4线程输出完全一致。

保持CPU、640、类别相关NMS IoU0.7、max_det300及同类一对一匹配IoU0.5。没有修改模型、数据、阈值或历史产物。匹配冲突为0；v2.11固定40文件完整性通过，14项针对性回归通过。不声明全仓测试通过。

## 解释与下一步

数值证据显示：该材质策略减少了无目标误检，但没有改善材质命中均值，且存在类别能力取舍。不能据此认定唯一病因，也不能把低FPR直接解释为学会了结构识别。

优先完成本轮新增漏检与全部无目标误检的逐框AI辅助审核，结合低阈值诊断判断是置信度变化、错类、定位不足还是未发现合格保留预测。尚未完成这一审核，本阶段状态为“数值评估完成、错误审核待完成”，不签发候选通过，不自动开启下一轮训练。

本测试只证明推理配置的速度与固定小批一致性，不替代下一轮训练CPU基准测试。所有产物training_admitted=false、promotable=false。
