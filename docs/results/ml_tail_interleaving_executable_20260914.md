# 持续核验结论：执行曝光顺序对照

## 唯一优先方向

执行常光条件的**集中尾段R1000 vs 交错I1000**对照。只改变原1000个完整批次的时间顺序，不补图、不改标签、阈值、学习率或BN策略。已完成三个真实加载器的18000次图像加载和3000批验证，并接入显式训练入口；当前没有开始训练。

## 为什么选这个方向

双向BN替换没有找到可直接应用的修复：换旧统计虽使光照召回均值提高5.56个百分点，却使无目标FPR由16.67%升至59.72%；反向替换也损害B900。不能将BN称唯一原因或无关因素。两组共同的集中尾段仍是优先线索，顺序对照可在不改变数据量的情况下验证。

已逐图查看本轮28页、111个证据卡，完成253条AI辅助审核：188个FP框、65个唯一图像真值目标（123次跨seed新增漏检事件）。FP内容为柜状块体63、杆体片段30、天空15、混合结构22、地面/阴影26、无法确认13、空ROI19。LOSS目标中清楚可辨14、遮挡18、截断24、无法确认9。视觉柜状外形不认证仿真资产类别；无像素级实例可见性认证。未知及空ROI有具名记录，全部保留原指标，没有自动通过或删除。

新审核工具首次遇到零高度框导致裁剪异常，已仅在独立工具中修正展示，明确显示EMPTY ROI。19个零面积框均来自R参数+B统计的seed27。在不替换正式指标的辅助统计中，忽略零面积框后三个seed仍有26/32/27张无目标图误检，即54.17/66.67/56.25%，均值59.03%。因此严重退化不是19个空框单独造成；正式FPR仍为59.72%。不得据此事后改变过滤阈值。

## 冻结执行方案

- 参考组：身份及权重有效的R1000三个seed，复用，不挑选checkpoint。
- 新组：I1000，seed7/17/27各独立初始化v2.11，1000步、6000曝光；CPU640、batch/nbs6、AdamW、恒定LR0.0005、无预热。
- 将原前900批按原顺序保留，将原尾100批按原顺序保留；每10个新位置中前9个放前段批次、第10个放尾批次。因此每50步恰有5个原尾批次。
- 每批6张及批内顺序不变，原亮度系数与对应图像一起随批移动，增强后的图像张量和完整监督张量逐批等同原来源批次；不是重抽增强。
- 每张图、类别实例、谱系及负例总曝光不变。**负例所在步数会改变**，这是顺序因素的一部分；本方案不宣称负例位置固定，也不能复用900步前缀训练状态。
- 不加入低光替换，避免同时改变两个因素；不修改BN更新方式、优化器或模型结构。
- 固定开发协议和历史能力保留门禁不变，分开报告相对R1000与B900的变化；改善R1000不等于恢复B900，更不等于正式验收。
- 只取终点last.pt。三个seed都完成后判断；不因部分seed结果调整顺序、追加预算或挑选有利seed。

## 已核验与边界

三个I1000加载器分别遍历全部6000曝光：成员顺序、batch6、完整cls/bboxes/batch_idx、增强图像哈希与来源批次一致；亮度before/after哈希一致。全程未创建优化器、未反向传播、未训练验证。

显式训练入口默认只核验审核、来源、预检、初始化环境和v2.11固定40文件，不训练。启动时再次核验；失败单元单独attempt留痕，每单元上限3次，语义失败不重试放行。当前入口直接运行单单元、不创建子进程，使用单元文件锁拒绝同seed同时启动。并发最多两个单元、各4CPU线程；给出的三条命令可按顺序执行。

在仓库根目录：

```sh
.venv/bin/python -m scripts.vision.train_tail_interleaving
```

仅打印THREE_CONFIGS_VERIFIED_NOT_STARTED。之后获得本轮训练授权，可分别执行：

```sh
.venv/bin/python -m scripts.vision.train_tail_interleaving --train --seed 7
.venv/bin/python -m scripts.vision.train_tail_interleaving --train --seed 17
.venv/bin/python -m scripts.vision.train_tail_interleaving --train --seed 27
```

本阶段找到并验证了可执行方向，不声称交错能改善模型。新训练后的评估仍需绑定新终点身份后运行，不用BN混合模型的输出代替。所有新产物training_admitted=false、promotable=false，不解封新场景。

## 产物

bn-statistics-diagnosis-v1/error-review-v1/evidence.json及review.json保存逐框图、输入哈希、AI辅助审核时间和决定。tail-interleaving-feasibility-v1/loader-feasibility.json保存精确排列、实际序列、逐批张量与每50步账本。独立脚本preflight_tail_interleaving.py用于真实加载预检，train_tail_interleaving.py用于默认核验/显式训练。历史协议、标签、权重及报告保持原样；框架标签缓存属于可重建派生产物，不作为历史身份替代。
