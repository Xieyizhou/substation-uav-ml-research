# 实例 128 的图缘框缺失：链路定位

## 当前明确结论

**缺失发生在我们收到的 Gazebo 原始框消息中，早于 Python 转换、训练导出和本轮材质变化。** 不是现有导出脚本删掉了一个已经收到的框。

已排除当前转换器的“小框自动忽略”解释；尚未定位 Gazebo 内部具体哪条渲染/投影分支丢弃该实例。因此可以称为原始框输出与可见实例不一致，不能直接宣布已经查明并修复了某一上游代码缺陷。

训练仍暂停。历史标签、世界、模型和已安装 Gazebo 未修改，没有新增忽略规则。

## 来源与重放证据

固定 T027 来源及 `west_switchgear_02`（标签 128），不改相机来寻找有利结果。

| 阶段 | 观察 |
| --- | --- |
| 原始采集回执 raw_truth | 只有标签 149、139、64、113、208，没有 128 |
| 原始回执转换后 truth | 同样五个实例，与原始消息一致 |
| 本轮原样重放的直接框消息 | 12 帧均没有 128 |
| warm 变体直接框消息 | 12 帧均没有 128 |
| cool 变体直接框消息 | 12 帧均没有 128 |
| 各单元选定的三帧稳定实例掩码 | 每帧均有实例 128 的 3,534 像素，外接范围 `[59,1052,306,1080]` |

36 条直接保存的消息均缺框；用于精确对齐结论的是各单元已通过原样/材质技术门禁的稳定窗口，不把任意前期帧都称为原帧对齐证据。

采集 C++ helper 把收到的 `AnnotatedAxisAligned2DBox_V` 完整序列化为 JSON，没有按面积、图缘或类别筛掉框。当前 Python 转换器对所收到的每个框执行类别映射和边界裁剪；有效框保留，零可见面积或非法标签会使该真值帧标为 invalid，不会把过滤后的子集静默称为完整有效帧。

## 实际运行的反例测试

以下仅在内存构造测试消息，不生成训练标签，也不追加到历史回执：

- 给原始消息追加 `[59,1052,306,1080]` 的实例 128 框，当前转换器保留它，帧有效。
- 1×1 像素的合法边缘框也被保留，说明当前转换没有最小面积忽略阈值。
- 超出边界但仍有正可见面积的框会裁剪保留，并标记 truncated。
- 裁剪后零面积的框或未知类别标签会使真值帧 invalid，不会静默通过。

这些测试核验的是当前转换逻辑；独立的原始消息证据已经表明本次缺失不可能由后续转换首次造成。

## 是否存在明确忽略策略

在本次检查的实际计划、canonical 采集和转换路径中，没有找到针对“这种底边片段可不标”的明确忽略规则。计划中的 `occlusion_filter` 是候选位姿筛选，不是全图标签删除规则；`annotation_revision` 名称也不能替代实际相机模式，保存世界实际使用 `full_2d`。

实例像素存在并不自动规定它应成为训练正例，但若希望忽略这类内容，就必须单独定义并验证监督策略及训练端忽略机制。当前不能把传感器没给框当作已经实施了合法忽略策略。

## 上游源码核对的边界

本机报告 gz-rendering 8.2.3、gz-sensors 8.2.2。对应版本源码显示，full_2d 框生成包含可见图筛选、视锥检查和投影范围筛选，之后传感器再发布框消息。这是下一步排查方向；尚未给本场景运行时各分支加观测，不能断言具体是哪一步失败。[渲染器源码](https://github.com/gazebosim/gz-rendering/blob/gz-rendering8_8.2.3/ogre2/src/Ogre2BoundingBoxCamera.cc)、[传感器源码](https://github.com/gazebosim/gz-sensors/blob/gz-sensors8_8.2.2/src/BoundingBoxCameraSensor.cc)

版本匹配源码不等于已完成已安装二进制的逐分支认证。没有升级、打补丁或切换生产标注模式。

## 下一步建议

在独立诊断副本中对同位姿同时比较 full_2d 与 visible_2d 框输出，并继续保留原 RGB、掩码和位姿/同步门禁。若可见框存在而 full_2d 缺失，可进一步缩小到完整框生成路径；若两者都缺失，应先查其共享可见图或分组逻辑。

此对照只用于诊断，不把 visible_2d 结果直接替换原训练框，也不将实例掩码外接框直接补进历史标签。确认机制后再制定独立修订方案。T036 非计划实例 118 的内容不足风险是另一个审核问题，不会因框链路定位而自动解除。
