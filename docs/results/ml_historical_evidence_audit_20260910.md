# 历史成果证据审计（2026-09-10）

## 核心结论

在本次可核验范围内，**没有发现主要分数的算术性高估，但发现明确的历史归因限制、指标命名歧义和身份序列化缺陷**。不能将这些不同问题合并成一个“水分百分比”。也不能因为复算差值为0，就声称标签无误或泛化已获证明。

最有依据的后续决策是：保留可复算的局部改进结论，撤销或限制过强的因果/泛化解释；先处理当前10个具名可见性证据缺口，不以追逐阈值为由继续追加训练。

- 对其中最近8个家族的24个单元，重新核验协议、训练回执、终点权重哈希和实际曝光与冻结计划一致。另9个历史参考单元检查评估及协议身份，但没有重新逐项验证训练过程，不能描述为同等深度的训练溯源。

## 需要保留、降级和修正的结论

### 可保留：降低学习率带来的有界开发收益

重新核验LR0.001与0.0005的逐seed采样序列、亮度系数和初始化完全相同。复算得到：原始计划命中75.00%→88.89%，光照50.00%→58.33%，原始全图召回66.67%→77.78%。这是有证据的固定条件下改进，不是全部成果无效。

但材质计划命中36.11%→38.89%时，全图召回28.33%→27.78%；光照未匹配预测增加，FPR并非各seed一致改善。原报告已记录这些限制。若口头表述成“材质能力整体提升”或“全部能力稳定提升”，应收回这种扩大解释。

### 必须降级：旧外观/背景实验的单因素因果结论

已有勘误明确：旧 `appearance-background-v1` 的24张图实际标注模式可能仍为visible_2d，声明却为full_2d；外观和背景组没有共同位姿，背景还同时改变光照。旧结果不能用于严格归因于颜色/背景。

这是对**该批实验严格因果用途的整体否定**，不是认定24张图全部无价值，也不能据此说“模型成绩高估100%”。本次引用并冻结已有勘误，没有重新采集这24张图。

### 必须限制：早期遮挡诊断的目标指标

已有来源审计记载：24张遮挡图中4张缺失计划实例，却因同类其他实例存在而接受；另有4个相机光心处于障碍物包围盒内，二者部分重叠，不可加成8张独立坏图。4/24=16.67%是对应单项风险帧比例，不是准确率被高估16.67个百分点。

本次没有重新逐帧重放该历史集合，其数值属于已绑定的既有发现。过去“类别被检出”不能替代“计划目标被检出”；后来的固定配对实验应与旧口径分开。

### 新发现：早期四权重评估的身份序列化缺陷

`paired-visual-factors-v1/evaluation.json` 的身份字段按读取后的JSON对象重算不一致，但输入文件哈希检查没有失败。源码生成 `development_weight_volatility.*.values` 时用整数seed作为字典键：哈希时排序为7、17、27；写JSON后键变成字符串，读取再排序为17、27、7。

只在内存中恢复这四处seed整数键，重算即得到保存的身份哈希，和原生成源码一致。此证据支持序列化排序缺陷，不支持数值篡改结论。历史文件未修改。严格通用身份校验仍会失败，后续复用须显式携带本次解释回执，不能静默忽略。

### 新发现：旧 `by_class` 不是当前逐类召回

早期四权重文件的 `by_class` 按“该帧计划采集哪一类”分组，随后统计这些帧中的所有类别真值。当前 `per_class` 则真正按实例类别过滤，两者分母不同。

例如冻结v2.11的原始条件：旧 `by_class.reactor.instance_recall` 为21.05%，统一的全图电抗器实例召回为40.00%。这不是模型突然提高18.95个百分点，也不是旧值一定偏高，而是不同指标。旧字段如果被读成“电抗器召回”就会误导。新审计只另存解释与正确口径，不改旧文件。

## 标签风险如何影响本次结论

当前逐框审核中10个目标仍因图缘片段或多实例重叠无法确认像素归属。它们仍保留在正式指标中，未删除、未置空、未按有利方向重算。

因此目前不能量化“正确修订标签后会改变多少分”。缺少独立确认时，给出某个水分百分比会制造新误导。可确认的是：近期还有清晰圆柱电抗器发生高IoU、低置信度漏检，不能把所有模型损失都解释成标签问题。

## 后续使用规则

1. 最近33个单元可继续用作固定开发集上的数值对照，但必须连同三seed、逐类损失和已知标签风险一起引用。
2. 旧外观/背景结果仅保留为历史问题诊断，不恢复其严格因果用途。
3. 早期四权重结果引用时说明身份序列化缺陷及 `by_class` 定义；不能把它和新 `per_class` 直接纵向比较。
4. 下一优先动作是独立核验当前10个具名目标，形成不覆盖原文件的勘误或证据补充。核验完成再冻结模型对照，不直接追加训练。
5. 已反复查看的开发图永远不重新称为盲测。封存新场景本次保持关闭。
