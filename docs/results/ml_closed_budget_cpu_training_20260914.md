# 重复预算对照：CPU 加速与训练启动

## 设计和训练门禁

根据六份已有权重、333张池成员的拟合诊断，本轮固定比较B450与B900，各seed7/17/27，六个独立v2.11初始化。900步重复M组完整2700次成员序列及亮度系数；前450步与短预算组相同。不只增加材质曝光，原始和负例也翻倍，因此结论限于完整预算变化。

CPU640、batch/nbs6、AdamW、恒定LR0.0005、无预热、仅冻结亮度不变。六配置真实加载预检完成24300次曝光、4050批；完整监督及图像张量的前缀和重复段一致。20项针对性回归通过；v2.11固定40文件核验通过（该核验不等于重新审核历史全部数据图像与标签）。不声明全仓测试通过。

## 训练 CPU 测速

使用实际训练入口、相同seed和前10个批次，每配置两个独立初始化任务。测速终点不形成候选，完整实验重新初始化。

| 配置 | 两任务总墙钟秒 | 每优化步均值秒 |
|---|---:|---:|
| 单进程4线程 | 56.624 | 0.829 |
| 单进程6线程 | 58.766 | 0.823 |
| 单进程8线程 | 56.853 | 0.825 |
| 双进程各4线程 | 32.262 | 1.192 |

选定双进程各4线程：两任务短程总耗时约1.75倍加速，计算段吞吐约1.39倍。单个进程变慢但两个单元并行后总吞吐提高；不能把1.75倍当作完整训练的已测收益。测试规模较小，包含初始化开销和系统负载影响，期间有短暂回归检查，需以完整训练实测更新估计。

同配置重复两次模型状态完全相同；双进程4线程与单进程4线程也相同。6/8线程与4线程状态不完全相同，因此不以旧训练未核实的线程数作为新预算对照的直接执行基准，两组都重新训练并使用同一CPU策略。

测速v1因当前库的损失项为字典、记录代码期待张量而失败。v2兼容两种形式，保留原失败证据与版本；没有修改学习率、科学约束或历史训练。新版通过真实短程重复及接口回归。

## 运行与边界

启动入口：`scripts/vision/train_closed_budget.py --train`。控制器按冻结顺序、最多两个进程推进全部六单元；入口默认只核验、不训练。每个单元重新校验预检、环境、初始化和CPU策略，逐批核对增强张量和完整监督，保存实际曝光和损失记录，最终只用last.pt。完整有效单元可复用，失败独立留痕，最多三次技术尝试，语义错误停止。

本次交付证明“已推进到训练”，不表示六单元已训练完成或模型已通过检测。实时启动证据另存training-start-confirmed.json，包含进程和检查点优化器步数；检查点本身会继续更新，不把它当作冻结终点。

按短程吞吐粗估六单元约45–70分钟，实际受加载、保存和资源竞争影响。当前控制器串联训练，不自动启动后续开发评估；没有定时任务或后台唤醒承诺。

不补采、不改标签、不调阈值、不解封新场景；全部产物training_admitted=false、promotable=false。阶段目标是验证预算是否改善训练拟合并保持能力，不预设模型必须通过，也不自动追加实验。
