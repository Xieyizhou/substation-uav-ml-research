# 扩大开发对照矩阵

已完成矩阵准备，尚未开始新采集。使用上轮三张地图中相同的普通柜体与开关柜源对象，枚举距离 6/10/16 米、高度 1.5/2.5/4 米、每 45 度一个方位。每组两个对象共享距离、高度、方位，背景和俯仰仍可能不同。

216 组候选中，40 组通过几何预检，共 80 个视角；其余 176 组保留明确排除原因（越界、相机占位或目标投影边界截断）。预检通过不等于采集成功或标签准入。

每个视角绑定源对象、占据边界、相机位姿、投影 AABB 及 9 条内部采样射线的通畅数量。投影区域仅用于后续诊断归因，不能当作可见轮廓或训练框；射线结果只是场景占据模型对遮挡的预测，需要实采核对。遮挡类别完整写入矩阵，完全遮挡对象不得计入可见目标漏检分母。

后续执行顺序：先将相机位姿按绑定传感器外参转换成采集器位姿，核验 FOV；分别采集清晰、部分遮挡和几何预测完全遮挡的诊断批次。保留所有捕获失败及拒绝帧，核对 RGB 和实际遮挡后冻结诊断区域，再复用 v2.11 的 640/0.37 推理设置。完全遮挡批次不能沿用“预期目标必须有框”的采集成功规则，需显式使用独立诊断规则，不能以伪造对象类别绕过检查。

未修改场景类别、旧标签、阈值或模型，当前训练候选及暂缓清单保持原状。矩阵不改变受保护评估集，未来实采仍为开发诊断。

生成脚本：scripts/vision/build_recovery_control_matrix.py。结果：data/research/ml_training_recovery_v1/control-matrix-v1/matrix.json，包含所有候选及排除原因、输入哈希和报告 identity。投影的中心、距离变化与相机后方边界测试通过。
