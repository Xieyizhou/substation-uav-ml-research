# CPU/MPS 短程训练加速验证

2026-09-10。结果：工程基准完成，MPS 有加速潜力；**尚未批准替换正式受控实验的 CPU 后端**。未启动新的450步三 seed 科学实验，未导出基准候选权重，历史结果保持不变。全部产物 `training_admitted=false`、`promotable=false`。

## 协议与实测

独立目录 `data/research/ml_training_recovery_v1/device-acceleration-benchmark-v1/runtime-fix-v3`。Apple M2 Pro，macOS 26.6.2，PyTorch 2.13.0，Ultralytics 8.4.107。

复用上轮冻结 seed 7 的前180次曝光及原位置亮度系数，batch/nbs=6、640、AdamW、恒定 LR=0.0005、无预热、amp=False。CPU-1 → MPS-1 → MPS-2 → CPU-2，各30优化步。前10步仅排除出稳定耗时统计，并非改变学习率预热。四次实际图像、完整标签及增强后批张量哈希一致，亮度日志逐项等于既有预检前缀。

使用同一真实 DetectionTrainer、数据集与加载器；禁用开发评估、末轮验证和权重保存。此区别与30步预算均明确登记，不能把短程结果当作450步科学对照。MPS CPU fallback 显式关闭；MPS预处理搬运为阻塞模式，保留了当前库实现。未启用混合精度、编译或改变批大小。

| 单元 | 第11–30步中位耗时 | 整段训练调用墙钟 |
|---|---:|---:|
| CPU-1 | 0.882秒 | 45.132秒 |
| MPS-1 | 0.381秒 | 34.081秒 |
| MPS-2 | 0.364秒 | 32.337秒 |
| CPU-2 | 0.867秒 | 43.929秒 |

稳定训练步统计中，CPU为0.874秒，MPS为0.373秒，CPU/MPS比值 **2.346倍**，即该部分耗时约减少57.4%。计入训练器初始化、数据加载等的短程墙钟均值为44.530秒对33.209秒，约 **1.341倍**，减少25.4%。这不是完整实验端到端加速率，不包括质量审核、固定开发推理、启动前输入身份核验及报告。

每步计时在输入哈希完成后、预处理开始前启动，在优化器及EMA更新完成后结束；MPS在边界同步，因此没有将异步提交时间当作实际GPU完成时间。图像加载、哈希、日志以及部分循环开销不含在此步耗时内。整段训练调用另计。同步方法依据 [PyTorch synchronize 文档](https://docs.pytorch.org/docs/stable/generated/torch.mps.synchronize.html)。

## 数值与可复算性

- 两次 CPU 的逐步损失和终点所有状态张量哈希一致。
- 两次 MPS 的逐步损失和终点所有状态张量哈希也一致；这是本机、该30步样本的观察，不是确定性保证。
- CPU/MPS首步三个损失分量最大绝对差约0.00002170，30步轨迹分量最大绝对差约0.03254；未预设且未事后添加“可接受差异阈值”，不宣称数值等价或精度不降。
- MPS日志明确警告 `scatter_reduce_mps`、`index_put_with_accumulate_mps` 没有确定性实现。当前库将确定性模式设为 warn_only，不能仅凭 `deterministic=True` 就认定严格可复现。
- 不同设备即使种子相同也不保证相同结果，符合 [PyTorch 可复现性说明](https://docs.pytorch.org/docs/stable/notes/randomness.html)。尚未验证450步后的开发指标、三seed波动或候选门槛，因此不能与既有CPU权重直接混合作为同环境策略对照。

## 技术失败与核验

CPU单元前两次技术尝试分别遇到：损失接口由张量变为字典；上层 YOLO.train 在30步结束后要求重新加载权重，与不导出基准权重的设置冲突。第三版使用命名损失并直接调用同一训练器，四个短程单元均完成。前两次失败目录和当时源码快照原样保留，快照哈希与各失败版本协议的脚本输入哈希相同；旧协议所指活动源码路径已更新，不能将它们冒充当前有效运行协议。没有继续重试或掩盖失败。

有效第三版输入与输出身份重新绑定。12项相关回归通过，v2.11固定40文件完整性通过；不声明全仓测试通过。历史实验完成回执再次验证有效。

## 下一步决策

现阶段可将MPS视为**待桥接验证的加速后端**，而不是已通过的科学替代后端。下一模型研究仍优先完成已有权重在共同已曝光、内容清晰成员上的拟合核对，区分训练侧退化与开发条件迁移，不因速度改善跳过病因核验。

如果后续决定正式采用MPS，需要独立冻结设备环境与数值差异说明，将同一轮参考组和新组统一放在MPS上，从v2.11重新独立初始化，保留三个seed及全部原门禁；不能中途把CPU训练续接到MPS，也不能只迁移新组后沿用CPU对照而不记录混杂因素。本次不执行该完整训练桥接。

产物：`protocol.json`、四单元逐步损失/批张量哈希/终点状态哈希、`summary.json`、`completion.json`。默认命令仅冻结核验，显式 `--run` 才运行30步工程基准。不存在候选模型、部署、保护标签读取或新场景评估。
