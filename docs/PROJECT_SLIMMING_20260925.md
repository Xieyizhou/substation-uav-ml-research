GitHub 普通 Git 会拒绝超过 100 MiB 的文件，建议仓库理想情况下小于 1 GB、尽量小于 5 GB。[官方说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)。当前源码体积已经适合上传；没有必要把数百 GiB 的实验数据一起放入仓库。

## 本次代码整理

用户选择保留桌面与主 CLI 功能，允许归档历史实验脚本。先建立完整基线、模块依赖图、当前飞行证据和模型访问清单，再按测试访问的历史回执补充保护范围。

- 最终将 **397 个历史视觉脚本、29,959 行**原样移入 `archive/research_scripts/vision/`。归档清单保存原路径、新路径和 SHA-256，全部校验一致。
- 初筛曾移动 923 个文件；回归测试识别出其中 526 个仍受历史回执依赖，已恢复原位。没有修改旧回执让迁移“通过”。

- HTTP GET/POST 使用明确的路由白名单；认证、参数提取、状态码、未知路径处理保持原行为。CLI 共用重复的注册、回执处理与退出码逻辑，原命令名保留。
- 将难例候选/去重、边框策略、多标签选择、YOLO 预测流、模型包校验、规划数据契约、航点策略与诊断分离；旧模块继续导出原有调用接口。
- 模型权重、数据集和实验输出均保留。归档是代码组织调整，本轮没有宣称释放数百 GiB，也没有删除历史研究数据。

## 源码导出与验证

新增 `scripts/export_source.py`，按照 Git 未忽略的当前工作树和源码目录白名单导出 ZIP，包含新写但未提交的源码、归档、测试与小型示例；跳过符号链接，拒绝超过 100 MiB 的源文件和覆盖已有 ZIP。`SOURCE_MANIFEST.json` 逐文件记录大小和 SHA-256。导出不会上传 GitHub、改动 Git 历史或打包本地 `.git`。

执行：`python scripts/export_source.py --output dist/source/uav-research-source.zip`。

重构前全量基线为 2,053 项，14 个失败、17 个错误；最后全量检查为 2,055 项，5 个失败、17 个错误，**没有新增失败项**。已消除 9 个模块长度违规。剩余问题是既有 SciPy 缺失、历史审核数据断言、旧标注与旧身份断言；不能将当前全量 CI 描述为全绿。

与改动直接相关的 111 项测试以及航点与模块边界 30 项测试通过。源码编译通过，Demo release gate 通过，当前视觉与原 LiDAR 飞行启动门禁、固定飞行模型和四个 Workbench 模型再次校验通过；本轮不重复起飞。完整测试与核验日志位于 `/private/tmp/uav-slim-*`。

## 后续边界

继续压缩活跃目录，最大的障碍是历史实验通过绝对路径和源码哈希绑定证据。后续应在新协议中将“冻结证据源码快照”和“当前产品实现”分开，再迁移仍受保护的历史脚本；不能直接删除它们或放松哈希校验。

若要降低本机 475 GiB 的实际占用，需另做数据保留分级、去重和冷归档。模型与必要训练集应独立管理并按需下载；GitHub 保存源码、配置、数据来源和校验清单。发布安装包可使用 Releases，训练数据另存。当前源码能上传，不等于新机器无需数据和仿真依赖就能执行完整训练与飞行。
